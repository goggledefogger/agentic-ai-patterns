# Quick-Win Scaffolding

When you bootstrap a new system (a vault, a project, a second brain), the trap is standing up structure that has earned nothing yet. The fix is to scaffold the minimal core, deliver one real result live in the same session, and name the mature patterns as opt-in seeds instead of building them.

## The Pattern

- Ask two things up front: the domain, and the one quick win the user wants today
- Research the patterns you already have, propose the plan as one reviewable block, and let the user confirm or redirect. Recommend then confirm, do not interrogate
- Scaffold the bare core only, enough to make the quick win real
- Deliver the quick win live in the same session. The actual goal advances, not just folders
- Write a SEEDS file that names mature patterns with an "adopt when" trigger, and build none of them yet

## Why It Works

- A live result on day one proves the system is worth keeping and earns the next step
- A minimal core avoids the maintenance tax of features nobody uses yet
- Seeds keep the long-term ideas from being lost without paying to build them early
- Recommend then confirm keeps the user in control without a long question-and-answer slog

## When to Use

- Bootstrapping any new vault, project, or knowledge system
- When the user wants momentum on the real goal, not on tooling
- Skip it when the system genuinely needs heavy structure before it can do anything useful, which is rare
